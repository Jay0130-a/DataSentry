# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

主要用户是**业务用户与审批人**：

- 财务人员：按月发起经营月报、费用明细报表，希望少手工取数；敏感数据自动进入审批。
- 经营分析人员：临时查询收入、毛利、预算差异，希望快速拿到口径一致的数据。
- 部门管理者：查看报表、审批敏感取数与发布；审批时必须看清批的是什么，过程可审计。

次要用户是**管理员/开发者**：接入 Source、查看工具契约、处理恢复、查登录审计。运维页面必须可用，但不以它为中心。

## Product Purpose

用一句自然语言发起报表任务，由 Agent 在受控工具、权限审批、可恢复状态和可回归事件轨迹的边界内完成：

```text
需求理解 → 跨系统取数 → 权限审批 → 报表生成 → 发布交付
```

成功意味着：业务用户不必学习结构化表单就能发起；审批人能在一次阅读里判断风险；任务中断后能从检查点继续；每一次越权、审批和发布都留下可查的证据。

## Positioning

不是让 Agent「会调工具」，而是让它在**权限、状态和审计**三条边界内工作：

- 工具调用先过 PreToolUse 权限链（ALLOW / ASK / DENY），跨 Workspace 访问被拒绝。
- 审批绑定具体工具调用、参数、草稿版本和接收人，不是一句笼统的「同意」。
- 任务状态与事件轨迹持久化，重启后从最后检查点恢复，不重新规划、不重放已完成步骤。
- 发布分「渲染待确认」与「确认投递」两步，投递前重新核对绑定。

## Operating Context

- 内网自托管，常通过 Docker Compose 启动；不能假设可访问外网 CDN。
- 默认 Mock 规划器，不调用模型、不产生费用；可切换真实模型。
- 界面语言为中文，日期/数字按 `zh-CN` 展示。
- 主要使用场景是桌面工作台（1280px 以上）；平板/手机只需不破版。
- 登录身份决定权限：`analyst`（业务用户）与 `admin`（管理员）；审批人就是登录身份。
- 既有界面为深色主题，用户已将其作为本次改造的既定约束。

## Capabilities and Constraints

页面与职责：

| 页面 | 可见身份 | 内容 |
|---|---|---|
| 任务 | 全部 | 全部任务、状态、步骤数、需人工介入数量；一句话发起 |
| 任务详情 | 全部 | 状态与标识、报表指标、发布、审批、检查点、工具调用 |
| 事件轨迹 | 全部 | 独立页面：按类型筛选、按关键字检索，序号与 JSONL 一致 |
| 审批 | 全部 | 待审批队列（绑定参数/工具版本/草稿版本/接收人摘要），批准或拒绝 |
| 恢复 | 管理员 | 恢复扫描结果，可「仅收敛状态」或「收敛并继续执行」 |
| 数据源 | 管理员 | Source 与工具清单，含敏感级别与副作用 |
| 审计 | 管理员 | 登录成功/失败/登出记录：账号、时间、来源 IP、User-Agent、失败原因 |

任务状态：`INIT`、`PLANNING`、`FETCHING`、`WAITING_APPROVAL`、`COMPUTING`、`VALIDATING`、`READY`、`DONE`、`PAUSED`、`BLOCKED`、`MANUAL_REVIEW`、`FAILED`。

技术约束：

- React 19 + Vite，样式为手写 CSS，不引入 UI 框架。
- 部署环境完全离线：不能依赖 Google Fonts 或其他外网字体请求；只使用系统字体或随包发布的字体文件。
- 前端隐藏入口只是第一层，权限边界在服务端；界面不能让用户误以为越权操作可用。
- 任务可见性由 Workspace 决定，不由发起人决定。
- 原始事件 JSONL 必须保持可下载/可查，界面翻译不能替代原始记录。

## Product Principles

1. **先回答「现在能不能发、卡在哪」**：状态、下一步和阻塞原因优先于装饰性信息。
2. **审批要能看清批的是什么**：绑定参数、工具版本、草稿版本、接收人必须在一屏内可判断。
3. **过程可审计**：关键动作留下可追溯记录，界面翻译与原始 JSONL 同时可取。
4. **角色边界不靠隐藏来保证**：前端不误导，服务端做真正的拒绝。
5. **离线、中文、桌面第一**：不为了视觉效果引入运行时外部依赖。

## Accessibility & Inclusion

未确认正式的无障碍标准。已知要求：深色界面的正文对比度必须可读，键盘可完成发起、审批和发布确认等核心操作；后续如需对外合规，再明确目标标准（如 WCAG AA）。
