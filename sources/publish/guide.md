# 报表发布网关 · 使用说明

## 这个 Source 由谁调用

**不是 Agent。** 发布由人工流程触发：发起发布确认 → 审批 → 确认投递。
因此它的工具不要求「先读 guide」——那条规则防的是 Agent 调用自己不理解的能力，
而发布的理解检查是**审批**本身（审批界面会展示文件、格式、接收人与内容摘要）。

这份 guide 记录的是发布网关的契约，供运维与接入方核对。Agent 只需知道：
发布发生在草稿产出之后，它不负责调用。

## 能力范围

| 工具 | 用途 | 副作用 | 敏感级别 |
|---|---|---|---|
| `publish_report` | 把指定格式的文件发布给接收人 | **publish** | internal |

## 发布格式

`format` 取值：`xlsx`（Excel）/ `docx`（Word）/ `pdf` / `md`（Markdown）。

格式是**审批绑定的一部分**：批的是「把这份 Excel 发给这些人」，
换成 PDF 就是另一件事，原确认会失效。

## 参数范围

- `reportId` / `draftVersion`：必须是当前草稿。草稿一旦重算，版本就变了。
- `recipients`：至少一个，且必须在当前 Workspace `allowedRecipients` 内。
- `channel`：`email` / `im` / `portal`。
- `fileName` / `artifactPath` / `sha256` / `sizeBytes` / `mimeType`：
  待投递文件的绑定信息。`sha256` 是**文件字节**的摘要——
  发出去的就是审批时承诺的那几个字节。

## 结果契约

- `receiptId`：回执编号。**发布结果只以回执为准**。
- `deduplicated`：为 `true` 表示网关判定这次投递与已有回执重复，返回的是**原回执**，没有再次投递。

## 幂等语义

网关按 `(reportId, draftVersion, recipients)` 去重。因此：

1. 同一草稿版本发给同一批接收人，重复调用不会重复投递。
2. 接收人**多一个少一个**，就是一次新的投递——去重键不同。
3. 草稿版本变化后，即使接收人不变，也是一次新的投递。

## 停止条件

1. 拿到 `receiptId` → 停止。
2. 收到「需要人工二次确认」的拒绝 → **立即停止**，等人工决定，不要换个渠道或缩减接收人重试。
3. 调用超时或结果未知 → 停止。**先查回执，确认没有投递成功之前不得重发。**

## 禁止事项

- 禁止在未经二次确认的情况下调用本工具。这是任何 Permission Mode 都不放开的业务合同。
- 禁止为绕过确认而拆分接收人、改用其它渠道或降低发布范围。
- 禁止把「网关返回了 deduplicated」解读成发布失败——它表示之前已经发过了。
- 禁止把本工具的调用参数（尤其是接收人名单）写进对外发布的报表正文。
